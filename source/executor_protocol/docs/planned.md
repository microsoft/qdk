# Planned features

[Protocol overview](../README.md).

What the crate offers now is in the other pages. This page lists what will
be added, each with a case that needs it, and what to do until then. None
of it is built yet.

## Building and running chains

| You will be able to                                               | For example                                                                         | Until then                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| run one chain under several seeds, the seed given with the job    | a code's tests over many seeds                                                      | build the chain again, giving the last executor `.seed(s)` ([Seeds](executors.md#seeds-not-generators))                                                                                                                                                                                                                                                      |
| run many jobs on one chain                                        | a service that runs many jobs, or a sweep of one program over parameters            | build the chain again for each job ([A chain and its job](composition.md#a-chain-and-its-job))                                                                                                                                                                                                                                                               |
| give your own crate's adapters and executors `>>` through a macro | a crate of codes, or of noise models                                                | join them with `compose(a, b)`, or write the impls by hand ([Which parts the operator joins](internals/composition.md#which-parts-the-operator-joins))                                                                                                                                                                                                       |
| have a static program's qubits derived from its calls             | a program that states no qubits, refused before it runs on a chain too small for it | state the qubits it uses with `Needs::with_qubits`; a call on a qubit the executor lacks is found at its batch only if that executor's check refuses it, and then the outcomes of earlier batches are dropped (`a_qubit_a_static_program_does_not_state_is_found_only_by_the_check_at_its_batch`; [A chain and its job](composition.md#a-chain-and-its-job)) |

## Writing adapters and codes

| You will be able to                                                             | For example                                                                                                                                 | Until then                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| refuse a call from an adapter's logic                                           | a code's adapter that refuses a call on a block that does not fit what it was built against, or what its state holds                        | refuse it in `.check(f)`, which runs before the state is made; an error from the logic fails the adapter ([Refusals and failures](adapters.md#refusals-and-failures))                                                                                                                                                                                    |
| state what an adapter offers and needs, with `.offers(..)` and `.needs(..)`     | a code that offers a logical qubit per block of three; a decoder that needs feedback below; a debugger that needs replayable shots below    | an `adapter_fn` offers what is below it, but for its instruction sets and seeds; an adapter written by hand states its offer when built ([An adapter written by hand](adapters.md#an-adapter-written-by-hand))                                                                                                                                           |
| read the replies below without holding the thread                               | an async caller over a code's adapter whose device answers later                                                                            | run the chain on a thread of its own ([Observers](guides.md#observers-a-profiler-and-a-debugger))                                                                                                                                                                                                                                                        |
| have a refusal below name the instruction the adapter was called with           | a repetition code written as a logic, whose run below names a physical instruction                                                          | the refusal names the instruction as sent below ([Refusals and failures](adapters.md#refusals-and-failures)); an adapter written by hand renumbers it with `Rejected::at_origin` ([How applications use it](instruction-sets.md#how-applications-use-it))                                                                                                |
| have an adapter send a refused call again, when its refusal's class allows it   | a device that refuses with `Later` while it cannot hold the states                                                                          | the caller sends it again, as the class says ([Rejections](rejections.md#a-limit-or-a-shortage-now-unmet-or-unavailable))                                                                                                                                                                                                                                |
| have the facilities check each call against the instruction set a part promises | a code's adapter over two devices, all made with the facilities, where each part checks again the set it promised                           | call `InstructionSet::check_batch` in the part's `.check` ([The checks](instruction-sets.md#the-checks))                                                                                                                                                                                                                                                 |
| give an adapter a log probability, with `.log_probability`                      | a noise model whose run reports each shot's log probability                                                                                 | a driver that needs `probabilities` is refused over an adapter that draws; the run of one that does not reports the last executor's log probabilities, which miss the adapter's draws (a known issue) ([Reports](adapters.md#reports-state_reportf))                                                                                                     |
| give each outcome a status set by a component below                             | a code's runtime that marks a readout unresolved (Qodec's `unresolved`), which the adapter above merges into the logical outcome it decodes | an outcome has no status; a component can count such readouts in its report at close, as a counting adapter counts what it sees (`a_counting_adapters_report_is_folded_over_its_shots`), but a count loses which readout was unresolved, so the adapter above cannot merge it into the outcome it decodes ([Reports](adapters.md#reports-state_reportf)) |
| read a call's shots in a logic with one state                                   | a debugger that logs each call by shot, with one state                                                                                      | give the adapter a state per shot, `.shots(OnePerShot)` ([A state per shot](adapters.md#a-state-per-shot-shotsonepershot))                                                                                                                                                                                                                               |
| map a runtime's results to the tags it sent, with a facility                    | a code's runtime whose results name no shot, as Qodec's do                                                                                  | write that glue in the logic, as the guide's runtime does ([A state that owns its way below](adapters.md#a-state-that-owns-its-way-below-owning_adapter_fn))                                                                                                                                                                                             |
| repeat a readout's tag within a batch, through a readout register               | a runtime whose result slots repeat within a batch, or one that defers measurements so that a batch holds several readouts                  | an executor that reports by tag refuses a batch that repeats one, with `check_unique_tags`, its reason naming this plan; an adapter can keep a register by hand ([Readout tags](replies.md#readout-tags))                                                                                                                                                |

## Executors, long runs and devices

| You will be able to                                                                      | For example                                                                                        | Until then                                                                                                                                                                                                                 |
| ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| keep a run's other shots when one shot fails                                             | a long sampling run whose device fails on one shot                                                 | a failure fails the whole executor, which refuses every later call ([An executor's whole life](executors.md#an-executors-whole-life))                                                                                      |
| send a failed call again and have it run                                                 | a long run on a device whose calls fail now and then, such as a GPU out of memory                  | a failed call fails the executor, as above ([Capabilities and needs](executors.md#capabilities-and-needs))                                                                                                                 |
| have a failed executor free its states at the failure                                    | a state of gigabytes held after its executor failed                                                | the states are kept until the executor is closed, which reports them, or dropped (`a_failed_executor_still_reports_the_states_made_before_the_failed_call`; [An executor fails](internals/executors.md#an-executor-fails)) |
| read each outcome's probability as it comes, and a shot's log probability during its run | a driver that weighs outcomes one by one as they stream, or stops a shot whose weight is too small | each shot's log probability comes in the report, at close ([Capabilities and needs](executors.md#capabilities-and-needs))                                                                                                  |
| hold shots on shared states, split where their values differ (grouped)                   | many shots of one program on a simulator whose shots rarely diverge                                | a state per shot, `.shots(OnePerShot)`, or an ensemble written by hand ([How an executor holds its shots](executors.md#how-an-executor-holds-its-shots))                                                                   |
| split a run's shots over several executors, their replies merged (sharded)               | a run spread over the cores, or over devices                                                       | run each shot on a thread of its own, `.run_on(OwnThread).shots(OnePerShot)` ([Where an executor runs](executors.md#where-an-executor-runs-run_on))                                                                        |
| place any executor on a thread, an adapter's or a chain included                         | a device's driver written by hand that must run on one thread                                      | run the chain on a thread of its own ([Where an executor runs](executors.md#where-an-executor-runs-run_on))                                                                                                                |
| place a state that is not `Send`                                                         | an engine's GPU context, or a state built on `Rc`                                                  | leave the executor unplaced, running on the caller's thread; placing it is a compile error, which no test pins ([Where an executor runs](executors.md#where-an-executor-runs-run_on))                                      |
| have an executor written by hand pass the run's seed up to the adapters that draw        | a noise model over your own simulator                                                              | an adapter that draws is refused over it; make the executor with `executor_fn` and `.seed(s)` ([Seeds](adapters.md#seeds-drawingid))                                                                                       |
| query an executor's state                                                                | the energy of a variational circuit, an expectation value of a Pauli sum                           | no message carries a query: a run gives the shots' readouts, and its report at close ([No state queries](internals/composition.md#no-state-queries))                                                                       |

## Callers and bindings

| You will be able to                                                                                                    | For example                                                                                                                  | Until then                                                                                                                                                                                                                                                   |
| ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| stop a run before its program ends and have its executor closed, on drop or through the run (which is not decided yet) | a user who interrupts a long run from Python, a timeout, or a driver that stops sampling once its estimate is precise enough | a run closes its executor only when its program ends; stopped earlier, the executor frees what it holds in its own `Drop`, if it has one, which no test pins ([Known limits](internals/composition.md#a-run-closes-its-executor-only-when-its-program-ends)) |
| cancel an executor's calls in flight when it closes                                                                    | a driver that stops sampling once its estimate is precise enough, with batches still queued                                  | closing a placed executor waits for the calls queued; dropping it cancels those not yet started ([Where an executor runs](executors.md#where-an-executor-runs-run_on))                                                                                       |
| choose a chain at run time                                                                                             | a chain composed from Python, a C API wrapping the protocol, or a transpiler chosen by a string                              | hold an `enum` of the chains you support, and refuse any other with a message that names this plan ([Known limits](internals/composition.md#a-chain-is-a-type))                                                                                              |
| reach an executor on another machine, each call run at most once over a link that may lose, repeat or reorder messages | a device behind a cloud service, or a simulator on another machine that a runner here drives                                 | no link is built; every refusal already says whether the work may have run ([A lost verdict](rejections.md#a-lost-verdict-planned-layers-l1-and-l0))                                                                                                         |
| read a refusal whose reason this end does not know, from a far end of a newer version                                  | a cloud service updated before the clients that call it                                                                      | no link is built, so no reason code crosses one; the codes are fixed now, so that the first deployed ends agree ([A reason this end does not know](rejections.md#a-reason-this-end-does-not-know-planned-decoder))                                           |
