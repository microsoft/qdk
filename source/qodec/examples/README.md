# qodec examples

Copies of the examples from the qodec repository's `examples/` directory, adapted to load in `qodec-repl` and `qodec-hi`, which share them. Each gadget circuit uses qodec's native inline YAML call list instead of Stim, because the published `qodec` crate has no Stim parser.

## Running an example

Pass a manifest or bundle to the REPL from the repository root:

```bash
cargo run -p qodec_repl -- source/qodec/examples/steane/steane.qodec.yaml
```

Then lower a program, for example `prepare_z 0; idle 0; measure_z 0`. Use `:isa` to list the top instructions. Commands also inspect the qodec, such as `:gadgets`, `:codes` and `:yaml`, and change it, such as `:edit`, `:set`, `:slice` and `:stack`. `:help` lists them all.

To edit an example and see, as you type, whether each gadget verifies and how a program lowers through every layer, open the same file in the terminal workbench (see [its README](../qodec_human_interface/README.md)):

```bash
cargo run -p qodec_human_interface -- source/qodec/examples/steane/steane.qodec.yaml
```

## Differences from the originals

- Each Stim circuit becomes one call per qubit, or per qubit pair for two-qubit gates, in the same order. For example, `CX 0 3 1 3` becomes `- CX: [0, 3]` and `- CX: [1, 3]`.
- The separate `.stim` files in `c4c6/c4/` are inlined into their gadget files. Their comments are kept as YAML comments.
- Everything else, including codes, ISAs, checks, readouts, and comments, has the same content, reformatted by Prettier. The shared physical ISA keeps its name, `stim.isa.yaml`.
- The originals' READMEs, Python builders, notebook, tests, and the C4/C6 paper source are not copied. Comments that mention them, such as "Generated by surface.py", refer to the qodec repository.

Under qodec's Stim parser, each converted gadget produces exactly the same calls as its original. The `examples_lower_their_programs` test in [`qodec_repl/src/tests.rs`](../qodec_repl/src/tests.rs) lowers a program through every example, and `every_example_runs_and_draws_at_every_boundary` in [`qodec_human_interface/src/tests.rs`](../qodec_human_interface/src/tests.rs) runs and draws each one.

## Benchmarks

[`qodec_repl/benches/bottom_throughput.rs`](../qodec_repl/benches/bottom_throughput.rs) measures, for every example, the time the lowering stack spends per bottom-ISA instruction it emits, while lowering whole shots into a bottom backend that does no work:

```bash
cargo bench -p qodec_repl
```

Append a name to run one example, for example `cargo bench -p qodec_repl -- steane`.
