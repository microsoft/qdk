API design and migration reference.

Make CodeProfile an analysis API, not a copy of its internal algebra

Keep the snapshot, error analysis, encoding, and distance searches. Remove duplicate group views and overlapping error predicates.

17 public members, including length

Counts cover named public class members, excluding the constructor and Python special methods. Twelve names remain, thirteen are removed, and five are added. The 12 module-level qdk.ec exports do not change.

Migration baseline: 407bf27cfa58bf587c2aee305db3f75a14728e4d. The contracts below describe the updated working tree.

The problem is meaning, not just length

For the two-qubit repetition code with stabilizer Z_0 Z_1, the error X_1 triggers a check but has an identity logical-basis component. Calling that error “trivial” hides the nonzero syndrome. is_logical checks both conditions and returns false.

The internal algebra retains its specialized predicates for propagation. The public profile exposes one predicate whose preconditions and result are explicit. Implementation.

  • One logical_effect_of method covers signed and phase-free conversion without separate aliases.
  • Generator tuples are the public representation. Callers needing groups can construct paulimer.PauliGroup directly.
  • logical_observable describes which logical value changes, rather than implying exact error-class targeting.
  • The equivalence predicate and explanation use the same options and comparison implementation.

Keep CodeProfile(code: qodec.Code). Do not add another code type, a profile factory, or an error-result wrapper.

All five operator collections are read-only properties returning tuples of independent Pauli copies. X and Z describe logical or gauge roles, not which physical factors occur. For example, a logical-X representative can contain physical Z factors.

logical_qubit_count distinguishes pairs from generators. length retains the established code-length name for the physical support count.

Contracts to tighten, not merely rename

1. Separate a logical component from a logical failure

profile.syndrome_of(error)
profile.logical_effect_of(error, including_phase=False)
profile.is_logical(error)

These answer three distinct questions: which checks change, which logical-basis component the error has, and whether it is an undetected logical failure. The last method earns its place because testing only the logical component gives the wrong answer for an error with a nonzero syndrome.

With including_phase=True, require a genuine signed logical action: the error must preserve the code space and differ from its logical representative only by a stabilizer and global phase. Otherwise raise ValueError, including for a nontrivial gauge action with no unique scalar phase.

With including_phase=False, return the phase-free component determined by commutation with the logical basis, even for an error with a syndrome or gauge component. This does not claim that a recovery was performed.

Phase-free conversion is an explicit option. Signed conversion never silently drops phase when the remainder is not a stabilizer.

All physical-error entry points must reject labels outside support. All logical-Pauli inputs must reject labels outside range(logical_qubit_count). Their docstrings must state the direction of conversion. Keep the existing Pauli type; do not add wrapper types solely to rename it.

2. Give the distance filter a user-visible meaning

profile.distance(
    *,
    errors: str | Sequence[Pauli] = "XYZ",
    logical_observable: Pauli | None = None,
    upper_bound: int | None = None,
    solver=None,
) -> Distance[Pauli]

profile.distance_bounds(
    *,
    errors: str | Sequence[Pauli] = "XYZ",
    logical_observable: Pauli | None = None,
    upper_bound: int | None = None,
    solver=None,
) -> Distance[Pauli]

With no observable, find any nontrivial logical failure. With logical_observable=Pauli("Z_0"), find an undetected error that flips logical Z₀. The observable uses logical indexes, must be nonidentity and Hermitian, and is not a physical representative.

Replace coset_representative with this option. Do not just rename the existing argument: translate the desired parity into the proper logical-observable commutation test. For two unencoded qubits, the old coset_representative=X_1 query corresponds to the new logical_observable=Z_1 query. It permits X₁ and Y₁ failures, not just the X₁ class.

Preserve all meaningful parity-filtered searches through an explicit migration. Exact logical-coset targeting is a different feature and remains deferred; do not imply that it exists.

Keep the current solver capabilities, including option objects, custom callbacks, and limits. solver is unannotated above only to avoid inventing a replacement public solver type. Its public configuration needs a shared decision with GadgetProfile, not a CodeProfile-only redesign.

Keep upper_bound aligned with GadgetProfile in this pass. Document it as a search cutoff, not a certified result bound, including the existing MWPF limitation. A shared cutoff redesign is deferred.

Every supplied Pauli remains one allowed factor, even if it affects several physical qubits. Preserve errors=[], infinite distance, lazy alternative witnesses, and the distinction between witness.factors and witness.product.

3. Use one equivalence policy

Give the predicate and explanation the same keyword-only options and one comparison implementation. Both must compare the same stabilizer and gauge spaces. strict_basis=True retains the chosen logical basis; False allows a different basis for the same logical group. Do not compare arbitrary gauge generators in the explanation while omitting gauges from the predicate.

Change including_signs to default to True. Signs can differ between generated groups even though qodec rejects explicitly signed input generators. For example, the groups generated by {XX, ZZ} and {XX, YY} differ in signs.

== is structural equality of the operator snapshot, separate from equivalence. Profiles are unhashable. Add hashability only for a demonstrated use.

New names

  • x: source is qodec.Code.x. Reject logical_x as a needless departure from the data model.
  • z: source is qodec.Code.z. Reject logical_z for the same reason; matching indexes preserve logical pairs.
  • gauge_x: extend the X axis with the existing gauge prefix. Reject x_gauge, which reverses the established naming order.
  • gauge_z: extend the Z axis in parallel with gauge_x. Reject z_gauge; matching indexes preserve gauge pairs.
  • is_logical: source is the package's logical-error terminology. Reject is_logical_failure as unnecessarily tied to an execution outcome and do not reuse is_logical_error, which had the broader zero-syndrome meaning. The docstring explicitly excludes identity and gauge-only changes.
  • including_phase: source is Pauli.phase, with the positive form of the existing including_signs option. Reject unsigned, which describes the omitted result rather than the requested capability.
  • logical_observable: source is the logical-observable terminology already used by channel analysis. Reject coset_representative: the search asks which observable changes, not which exact error class to produce.

Implementation boundary and acceptance checks

This is a breaking API update. Obsolete public aliases are removed; repository consumers use the new contracts. Internal algebra methods used by propagation and encoding remain available to those algorithms.

  1. Pin set(name for name in dir(CodeProfile) if not name.startswith("_")) to the 17-name set, in both directions. Keep the 12-name module surface pin.
  2. Test identity, detectable errors, undetected logical errors, gauge-only changes, and out-of-support labels. Check that a detectable error with a logical component is not called a logical failure.
  3. Test phase-preserving conversion and explicit phase-free conversion, including signed stabilizers, nontrivial gauge components, and physical/logical round trips.
  4. Test tuple/copy behavior and stable syndrome indexes. Preserve custom encoding order; reject duplicate or missing physical labels at the boundary.
  5. Test that equivalence agrees exactly with an empty explanation for every option combination, including stabilizer signs, logical-basis changes, and gauge-space differences.
  6. Preserve correlated unit-cost errors, impossible failure, open bounds, witness replay, and all supported solvers. Test the observable filter on multiple logical qubits and prove the old parity queries have an explicit translation.
  7. Migrate the public-surface tests, profile tests, distance consumers, and notebooks. Replace forwarding-equivalence tests with observable contracts where behavior is being clarified.

Executable contract

The exact public surface is pinned by surface tests. Error, phase, gauge, and equivalence behavior is covered by profile tests; observable constraints and parity migration are covered by distance tests.

Consumer discovery covered the checkout's tests, implementations, and sample notebooks. It does not establish that external callers do not use any removed member.
