Reading the report

A diagnostic gives the rule, artifact location, discrepancy, and evidence. Layer indices are zero-based; (C4 -> stim) names the source and target instruction sets. Reference lists are copyable into qodec checks or readouts; a parity-one relation carries a separate caveat.

  1. 01 Structural1 declaration and reference rules
  2. 02 Semantic8 algebra, action, and parity rules
  3. 03 Informational4 declaration-coverage rules

print(report) prints errors and warnings, followed by totals. Informational entries remain in report.informational but are not printed individually. INFO examples below use the same block layout to show those fields.

Parity contract: noiseless execution on valid input codewords, with arbitrary incoming Pauli-frame signs. An encoding sign tracks the known Pauli correction associated with that block; it is not a second measurement of the logical state. Readouts must account for these signs. The authored C4 measurement readouts omit them and now receive mismatch diagnostics.

Each example is one actual finding with totals omitted. The capture runs enabled one rule at a time. A normal audit may report several findings for the same edit; no protocol files were modified to produce these examples.

Invalid model structure
qodec/invalid-structure

Audit finds an invalid protocol declaration: incomplete layers, code-list shapes or capacities, action or parameter uses, circuit calls, reference bounds, or artifact connections.

These checks live in audit. qodec load/save enforce only preservation preconditions, so incomplete protocols, unequal code lists, partial readouts, and invalid source text can persist. Findings carry locations; dependent analysis is skipped while unrelated artifacts remain checkable. Opaque circuit-record bounds remain unknown. A whole readout omission is informational; a supplied partial list is an audit error.

Add out[5].stabilizers[0] to a measure_zz check. This destructive measurement has no output encodings.

ERRORTarget: InstructionSet and detached GadgetRule source

Invalid Clifford map
instruction-set/invalid-clifford

A Clifford action does not preserve commutation relations on the complete generator basis.

Unlisted generators have identity images and participate in the check. The same precondition runs before native Clifford construction, avoiding a native panic for invalid maps. Unsupported generator forms produce a warning. Invalid maps block dependent gadget analyses.

Example · Implicit identity violates commutation

Declare X_0 -> Z_0 without specifying Z_0. Its implicit identity image is also Z_0, so the pair no longer anticommutes.

[ERROR] instruction-set/invalid-clifford
layers[0].instruction_set (C4)
instruction 'invalid_map' action[0]: invalid Clifford map
    Images of X_0 and Z_0 must anticommute: X_0 -> Z, Z_0 -> Z. Unlisted generators have identity images.
ERRORTarget: CodeRule source

Invalid code algebra
code/invalid-algebra

Declared stabilizers or logical operators violate the algebra required of a code.

Stabilizers must commute with each other and all logicals. Each logical X/Z pair must anticommute; distinct logical pairs must commute. The message names conflicting operators. Algebraic code analysis enforces its own preconditions, including consistency of the stabilizer group. qodec can load and save these drafts; audit reports their mathematical errors.

Example · Commuting logical pair

Replace the C4 logical Z operators with its logical X operators. The draft remains representable and serializable.

[ERROR] code/invalid-algebra
codes['C4']
x[0] and z[0] must anticommute
    x[0]: X_0 X_1
    z[0]: X_0 X_1
WARNINGTarget: GadgetRule source

Unsupported action atom
gadget/unsupported-action-atom

An instruction contains an action step that the logical-action verifier cannot handle. The message identifies the step index and type.

The action verifier accepts Stabilize, Observe, and unconditional Pauli/Clifford steps. An unsupported step skips the action comparison; it does not establish that the instruction is invalid.

Example · Unsupported action step

Give x0 a Rotate action, which this action verifier does not support.

[WARNING] gadget/unsupported-action-atom
layers[0].gadgets['x0'] (C4 -> stim)
implements.action[0] (Rotate) is not supported by the action verifier
    Logical action not checked.

Check mismatch
gadget/check-mismatch

A declared check is not identically zero during noiseless execution. It may be random, depend on the incoming frame or logical state, or be deterministically one.

The full equation is evaluated, including encoding signs and resolved gadget-readout references. Repeated terms cancel. A nonzero result is an error; unavailable analysis is a warning. An empty or algebraically empty equation is always zero, but supplies no constraint.

Flag mismatch
gadget/flag-mismatch

A bound flag can be one without a fault, violating the noiseless-zero flag contract. The message identifies the flag and its declared equation.

Flags now receive semantic verification instead of an unconditional flag-content-not-checked notice. An always-one or random flag is an error. Inconsistent or undetermined flag dependencies are errors too. Unsupported analysis produces a warning; a trivial empty flag is valid.

Action mismatch
gadget/action-mismatch

The circuit action differs from the implemented instruction. One witness identifies a missing or unexpected logical observable/stabilizer, a differing output image, or a sign-parity difference.

A completed comparison emits an error. A handled failure emits a warning, or an informational entry if the failed comparison concerns a preparation with outputs and no inputs. Resetting an input is allowed when it matches the instruction action.

    Expected measured logical observable X; absent from the circuit's group.

Readout mismatch
gadget/readout-mismatch

A complete readout equation disagrees with the intended logical outcome, or its dependencies are inconsistent or do not determine that outcome.

Verification includes arbitrary incoming Pauli-frame signs, not only a zero-frame input. Equivalent equations pass even when their term lists differ. A verified replacement is shown when one is expressible in circuit bits and input signs. Readout dependencies are solved as binary linear equations: a cycle is allowed if it has a unique, consistent result. Unsupported analysis produces a warning.

Incomplete output frame
gadget/incomplete-output-frame

The valid declared relations do not determine an output stabilizer sign from available input signs and circuit measurements.

The test uses the span of the equations, not mere reference presence. Duplicate terms, dependent equations, and invalid checks cannot manufacture a complete frame. Readout definitions do not count as independent known bits. Missing declarations remain warnings. A derived parity-one relation is shown as terms plus a separate caveat; it is not a valid zero-parity check.

INFOTarget: InstructionSetRule source

Unreferenced block
instruction-set/unreferenced-block

A declared block type is unused by the inputs and outputs of every instruction in its instruction set.

No finding is emitted when no instruction references any block type.

Example · Unused block type

Add a one-qubit block type named spare to C4, without using it in any instruction. Displayed from report.informational.

[INFO] instruction-set/unreferenced-block
layers[0].instruction_set (C4)
block type 'spare' is unused by instruction inputs and outputs
    Declared capacity: 1 qubit(s).
INFOTarget: GadgetRule source

Missing observable
gadget/missing-observable

An instruction declares an Observe outcome, but the gadget has no readout binding at that position. One finding is emitted per missing outcome.

An entirely omitted list is allowed for later derivation. This is informational, even when warnings are promoted. It does not check whether the circuit measures the right observable. Logical observables precede flags.

Example · Unbound logical result

Remove all readout bindings from measure_xx, whose instruction declares two logical X outcomes. Displayed from report.informational.

[INFO] gadget/missing-observable
layers[0].gadgets['measure_xx'] (C4 -> stim)
readouts[0] is unbound (logical X_0)
    Expected: 2 observable bindings; declared: 0.
INFOTarget: GadgetRule source

Missing flag
gadget/missing-flag

An instruction declares a flag, but the gadget has no binding for it after the Observe outcomes in its readout list.

An omitted list is informational and may be supplied by derivation. A supplied partial list is a structural error. The flag-mismatch rule separately verifies bound equations.

    Expected: 1 flag bindings; declared: 0.
INFOTarget: QodecRule source

Missing realization
gadget/missing-realization

An instruction in a non-bottom layer has no explicit gadget under the same name.

This can be intentional: synthesis may supply the lowering instead of a stored gadget. The finding remains informational even with promote_warnings=True. The bottom layer is excluded.

Example · Instruction without a gadget

Remove the idle gadget while retaining the idle instruction. Displayed from report.informational.

[INFO] gadget/missing-realization
layers[0].instruction_set.instructions['idle'] (C4 -> stim)
No explicit gadget for instruction 'idle'
    No entry: layers[0].gadgets['idle']

Report options

report = ec.audit(protocol)
print(report)

errors = report.errors
warnings = report.warnings
information = report.informational

report.ok means there are no errors. To display informational entries:

for diagnostic in report.informational:
    print(f"[{diagnostic.severity.name}] {diagnostic.rule}")
    print(diagnostic.where)
    print(diagnostic.summary)
    for line in diagnostic.detail.splitlines():
        print(f"    {line}")
    print()

Disable a rule by exact ID, or promote warnings:

report = ec.audit(protocol, disabled=("gadget/missing-realization",))
strict_report = ec.audit(protocol, promote_warnings=True)

Informational entries are not promoted. Structural and algebraic failures block dependent analyses, including shared instruction-set occurrences. A whole-model failure blocks all semantic analysis; unrelated gadgets continue when the failure is local. Code and instruction-set algebra run before gadget verification.

Coverage and provenance

The catalog matches default_rules() exactly: 13 IDs, with 7 ERROR, 2 WARNING, and 4 INFO defaults. The obsolete prepared-input rule and unconditional flag-content-not-checked notice are not registered.

Message examples were captured from fresh in-memory copies of the notebook's C4 protocol, or small flag-only circuits over its physical instruction set. Each scenario is described alongside its unedited diagnostic text. Source links identify the implementation used for this snapshot.

Analysis limits: the parity verifier currently declines opaque source formats, conditional or selected circuit calls, conditional circuit actions, and circuit flag bits. Logical readout verification declines interleaved logical actions and noncommuting logical measurements. Output logical-frame references after logical measurements or outcome-dependent output frames are reported as unsupported. These cases produce scoped warnings, not invented parity results. Empty equations remain identically zero.

A clean report does not prove fault tolerance. qodec preserves resolved declarations; audit checks protocol correctness, including declaration validity and mathematics. Loading a draft is not certification. Missing files, ambiguous definitions, and values that cannot survive a faithful round trip still fail in qodec. Redundant-check notices and fault-model-dependent checks are not included.
